Problemstellung

Ein Aktienportfolio von Hand zusammenzustellen ist zeitaufwändig und fehleranfällig.

  • Risikobereitschaft einschätzen
  • Markttrends verfolgen & filtern
  • Dutzende Aktien durchforsten
  • Fundamentaldaten prüfen
  • Allokation & Risikomanagement
Die meisten Leute überspringen die Hälfte dieser Schritte — oder verlieren sich in Analyse-Paralyse.

💡 Unsere Lösung

Mauerstrassen Agent automatisiert den gesamten Prozess: Kapital, Risiko & Horizont angeben → fertiges Portfolio mit konkreten Positionen, Kaufkursen und Stop-Losses.

Task-Pipeline

Das Manager-LLM führt 5 Tasks sequenziell aus. Die ersten zwei fragen den User, ab Task 3 läuft alles automatisch.

1

Strategy Task

User-Input sammeln, Strategie erstellen & validieren

👤 Human Input
2

Trend Task

5 Markttrends finden, User wählen lassen

👤 Human Input
3

Screening Task

Top 5 Aktien pro Trend über Web-Suche finden

⚡ Automatisch
4

Checker Task

Fundamentaldaten via Finnhub MCP validieren

⚡ Automatisch
5

Portfolio Task

Finales Portfolio mit Allokation & Stop-Loss bauen

⚡ Automatisch

Kontext-Abhängigkeiten: Jeder Task deklariert explizit seine Vorgänger — z.B. Screening hängt von Strategie + Trends ab.

Output: Das finale Portfolio wird als strukturiertes Markdown nach output/portfolio_recommendation.md geschrieben.

Technologie: MCP Server

Eigener Finnhub MCP Server mit FastMCP — kommuniziert über stdio-Protokoll und liefert Echtzeit-Finanzdaten an den Stock Checker.

# finnhub_server.py from mcp.server.fastmcp import FastMCP mcp = FastMCP("finnhub-financial-data") @mcp.tool() def get_company_profile(symbol: str): """Get company profile: name, sector, industry, market cap.""" return _get("/stock/profile2", ...) @mcp.tool() def get_quote(symbol: str): """Real-time stock quote.""" return _get("/quote", ...)

Hierarchischer Prozess

Statt eines einfachen sequentiellen Ablaufs nutzen wir einen hierarchischen Prozess mit einem Manager-LLM — quasi wie ein Senior-Portfoliomanager, der ein Analysten-Team leitet.

  • Manager-LLM entscheidet, welcher Agent wann dran ist
  • Fasst Zwischenergebnisse zusammen
  • Stellt sicher, dass jeder Task den Kontext seiner Vorgänger erhält
  • Orchestrierung selbst wird von einem LLM übernommen
# crew.py — Hierarchical Process @crew def crew(self) -> Crew: return Crew( agents=self.agents, tasks=self.tasks, process=Process.hierarchical, manager_llm=os.getenv("MANAGER_MODEL"), )

Reflexion & Lessons Learned

📦 Finnhub-Antworten sind riesig

get_financials_reported liefert komplette Finanzberichte über mehrere Perioden. Wenn der Stock Checker das für mehrere Aktien hintereinander aufgerufen hat, ist der Kontext explodiert und frisst sehr viel Tokens.

🔄 Human-Input-Konfiguration passte nicht zusammen

Wir haben human_input=True auf zwei Tasks gesetzt, aber es hat auch den Stock Screener manchmal nach Input gefragt.

📊 Aktienanzahl schwankt

Wir haben Top 5 Aktien pro Trend verlangt, aber das LLM hat manchmal drei oder sieben zurückgegeben. Exakte Anzahlen wurden nicht immer eingehalten.

📝 Strukturierter Output unzuverlässig

Das Pydantic-Schema für das finale Portfolio wurde nicht immer eingehalten. Felder wurden übersprungen oder falsch formatiert.
